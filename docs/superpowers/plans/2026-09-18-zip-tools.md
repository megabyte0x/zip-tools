# ZIP.tools Website v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a greenfield ZIP.tools website that searches, lists, boards-by-NU, reads, and graphs ZIPs from a pinned `zcash/zips` snapshot.

**Architecture:** A `zip-index` CLI walks the snapshot, parses RFC-822-ish headers, extracts citation edges, merges a committed `nu.json` overlay, converts RST at build time, and writes one `zip-index.json`. Next.js App Router reads that JSON only — no live GitHub, no database. MCP is out of this plan.

**Tech Stack:** pnpm workspaces, TypeScript, Node `node:test` + `tsx` for the indexer, Next.js App Router, CSS modules + a token file, `react-markdown` + GFM + math, pandoc for RST. No Chakra, no Tailwind, no Mongo, no OpenAI.

**Spec:** `docs/superpowers/specs/2026-09-18-zip-tools-design.md`

## Global Constraints

- Complement zips.z.cash; do not replace it. Always link official + GitHub.
- Content is a git submodule of `https://github.com/zcash/zips` at `submodule/zips`. Freshness = pin.
- Runtime never talks to GitHub. `zip-index.json` and rendered HTML are build artifacts, gitignored.
- Fail the index build only if the snapshot dir is empty or the JSON cannot be written.
- UI copy for edges is **Cites / Cited by**, never Requires, unless a real `Requires` header produced that edge.
- v1 indexes only snapshot files `zips/zip-*.{rst,md}` and `zips/draft-*.{md,rst}`. No reserved stubs.
- One UI system: CSS modules + tokens. No Chakra, no Tailwind in v1.
- No per-row updated column. Footer shows snapshot SHA + date.
- MCP (`packages/mcp`) is v2 — do not create it in this plan.
- Conventional Commits on every commit: `type(scope): lowercase imperative`, no trailing period.
- Do not `git push` unless the human explicitly asks.

## Scope

This plan is website v1 only (spec steps 1–8). Do not implement MCP. Do not fork eip-tools.

- [ ] **Step 3: Write minimal implementation**

Algorithm:

1. Take lines until the first underline heading (`===`) or ATX `# ` heading.
2. If the block starts with `::`, skip that line.
3. Parse `Key: value` rows; continuation lines that do not contain `:` at the start of the trimmed line belong to the previous key (Owners).
4. `ZIP` → integer or null. `Owners` → split on newlines, each `Name <email>`. `Discussions-To` → strip `<>`. `Requires` → integers.
5. Missing Title/Status → warning, empty string.
